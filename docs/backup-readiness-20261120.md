## Сначала получить реальную копию БЕЗ изменения production

1. На доверенном локальном компьютере установить официальные Supabase CLI и Docker Desktop, проверить `supabase --version` и `supabase db dump --help`. Использовать официальное руководство: https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore .
2. Получить подключение к **этому** проекту через Dashboard → Connect → Session pooler и пароль базы; не публиковать пароль, строку подключения, дампы, user email, UUID, ответы или refresh tokens в чате/GitHub. Не сбрасывать действующий пароль только ради проверки: это может повлиять на рабочие соединения. Использовать секреты только локально.
3. Создать отдельную приватную директорию **вне репозитория GitHub** с ограниченными правами. Используя официальную процедуру `supabase db dump`, выгрузить **roles.sql**, **schema.sql**, **data.sql** (параметры `--role-only`, стандартная схема, `--data-only --use-copy`). Зафиксировать версию CLI и UTC-время.
4. Отдельно убедиться, что набор дампов действительно включает данные **auth/users**, classroom, progress, finance events и **все** существующие пользовательские схемы. В CLI по умолчанию исключаются определения управляемых схем `auth`/`storage`; механически считать стандартные три файла полным образом нельзя. Проверить правила восстановления управляемых схем и миграций в официальной документации. При наличии custom auth/storage schema changes сохранить соответствующие определения и `supabase_migrations` отдельно.
5. Вести манифест `sha256` и размеров всех файлов в приватной папке; скопировать зашифрованный архив в независимое хранилище с ограниченным доступом. Не хранить его в GitHub Pages или общем Google Drive.
6. Восстановить копию **только в изолированной локальной или отдельной тестовой среде** (не на действующем проекте). Операции restore/DDL/SEED на production запрещены. Перед отдельным облачным тестовым проектом согласовать стоимость.
7. Проверить восстановление: наличие таблиц, ролей, политик, необходимых функций/миграций; сравнить числа строк основных таблиц с замороженным baseline, проверить целостность связей и доступов на синтетических или авторизованных тестовых аккаунтах. Сохранять только агрегаты и результат проверки, не приватные данные.
8. Отдельно предложить каждому ученику, чей прогресс хранится только в браузере, локальный export + безопасный import без перезаписи. Это обязательный отдельный пункт, даже если серверная копия восстановилась.
