# Правила разработки GoStudy — обязательны для всех исполнителей

## Источник истины: кабинет Михаила

Эталонный кабинет: `student-business-ai-finance.html`.
Эталонный урок: `business-ai-finance-b2-02.html`.

**Единый интерфейс — это работающие общие компоненты, а не визуальное сходство.**
Нельзя создавать отдельные кабинеты или уроки со скопированными HTML/CSS/JS: внешне они могут выглядеть похоже, но перестанут получать общие обновления.

- Кабинеты: `assets/gostudy-v1-cabinet.css` и `assets/gostudy-v1-cabinet.js`, настройки только через `#cabinet-settings`.
- Уроки: `assets/gostudy-v1-lesson.css` и `assets/gostudy-v1-lesson.js`, учебное содержимое отделено от общей оболочки. Для защищённых уроков загрузка шаблона может быть динамической.
- Словарь: общий компонент тренировки; данные ученика изолированы по ID.
- Новые общие компоненты сначала проверяются на Михаиле, затем согласуются с заказчиком и только после этого распространяются.

## Шесть этапов новых общих функций (Михаил)

1. Разработано.
2. Опубликовано.
3. Проверено реальными сценариями ученика и преподавателя.
4. Согласовано заказчиком.
5. Распространено на остальные применимые кабинеты.
6. Проверено после распространения.

**Это строгий процесс для разработки нового стандарта на эталонном кабинете Михаила.**
Для Дарьи и других учеников применяем уже утверждённые компоненты без повторения шестиэтапного согласования; новые функции не должны самовольно становиться общим стандартом.

## Авторизация и доступ

GitHub Pages — публичный статический хостинг. Скрывать учебный текст стилями или JavaScript **не является защитой**.
Контент, доступный только ученику, хранится в Supabase и выдаётся через JWT + RLS. Шаблон HTML может быть публичным, но не содержит закрытый текст или ответы.
- Общий клиент входа: `assets/gostudy-private-access.js`; он использует существующие ключи сессии GoStudy.
- Материалы: `public.gostudy_private_lessons`, политика чтения только для владельца и назначенного преподавателя.
- Слова: `public.gostudy_vocabulary_items`, доступ через RLS; клиент `assets/gostudy-private-vocabulary.js`.
- Прогресс: `public.gostudy_progress`, сохранять без потери предыдущих данных.
- НИКОГДА не помещать пароли, service_role / secret API keys или частные уроки в публичный HTML/JS.

## Добавление нового ученика или урока

1. Сначала изучить последние файлы Михаила и общие компоненты. Не полагаться на старые скриншоты или описание «похоже на GoStudy».
2. Добавить ученику конфигурацию существующего кабинета, не копию интерфейса.
3. Назначить действующие права доступа в Supabase, проверить прямые ссылки без входа и под другой учётной записью.
4. Создать **новые** оригинальные учебные материалы с ключами и методической проверкой.
5. Сохранить ранее добавленные слова, ответы и сообщения при миграции. Старые страницы архивировать или перенаправлять только по согласованному плану.
6. Проверить на ПК и телефоне, под учеником и преподавателем, включая повторную загрузку, словарь и сохранение.
7. Выполнить `node scripts/check-architecture.cjs`. Зарегистрировать новый кабинет в архитектурном контракте, если он появился.
8. Разделять статусы «коммит в GitHub», «сайт опубликован» и «сквозное тестирование завершено». Не выдавать одно за другое.

## Контроль качества

`.github/workflows/gostudy-architecture.yml` проверяет общие шаблоны. Этот контроль не заменяет браузерные E2E-тесты и не гарантирует блокировку публикации при отсутствии настройки правил защиты ветки.
